# test_exc1.txt – Exception handler at address 0x0 with mret
#
# Scenario:
#   1. Normal code at 0x80000000 executes ebreak → trap to mtvec=0x0
#   2. Exception handler at 0x0: fix up mepc, then mret
#   3. Execution resumes at 0x80000004 (past the ebreak)
#   4. One more instruction, then falls into zero memory → clean stop
#
# DII buffer order (what the simulator receives in sequence):
#   [Step 0] PC=0x80000000: ebreak         → triggers M-mode trap, PC→0x0
#   [Step 1] PC=0x00000000: csrr x1, mepc  → handler: read faulting PC
#   [Step 2] PC=0x00000004: addi x1, x1, 4 → advance past ebreak
#   [Step 3] PC=0x00000008: csrw mepc, x1  → write updated mepc
#   [Step 4] PC=0x0000000c: mret           → return, PC→0x80000004
#   [Step 5] PC=0x80000004: addi x2, x0, 42 → result marker (x2=42)
#
# Memory state captured in dump ELF:
#   [0x00000000..0x0000000f] handler: csrr / addi / csrw / mret
#   [0x80000000..0x80000007] main:    ebreak / addi x2,x0,42
#
# Re-execution from dump ELF:
#   Same steps play out identically; terminates when PC hits zero memory.

# ── Main code at 0x80000000 ─────────────────────────────────────────────
0x00100073   # ebreak  (→ trap to 0x0)

# ── Exception handler at 0x0 (written by DII after trap) ────────────────
0x341020F3   # csrr x1, mepc          ; load faulting PC into x1
0x00408093   # addi x1, x1, 4         ; skip past ebreak
0x34109073   # csrw mepc, x1          ; write updated return address
0x30200073   # mret                   ; return to 0x80000004

# ── Resumed execution at 0x80000004 ─────────────────────────────────────
0x02A00113   # addi x2, x0, 42        ; x2 = 42  (observable result)
